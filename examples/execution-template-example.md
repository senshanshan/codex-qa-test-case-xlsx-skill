# 执行版模板示例

如果你的工作希望生成出来的工作簿更接近“执行单”而不只是“设计单”，可以参考这个示例。

## 为什么有这个模板

默认 schema 有意不包含 `实际结果`，因为这套 skill 默认先聚焦“测试用例设计”（由此辅助你或者agent来完成前置用例任务）。

如果你的团队习惯直接在生成后的工作簿里执行测试，可以保留默认列，再通过 `extra_columns` 追加执行类字段。

## 推荐追加列

- `实际结果`
- `执行人`
- `执行日期`
- `是否通过`
- `需求编号`
- `是否自动化`

## 示例提示词

```text
使用 $test-case-xlsx-generator 根据这份 PRD 和这些登录页截图生成分类测试用例。

system_name: Demo System
module_name: Login and Password Reset
output_dir: C:\Users\YourName\Desktop\TestCases
extra_columns: 实际结果, 执行人, 执行日期, 是否通过, 需求编号, 是否自动化

请：
1. 先构建覆盖地图。
2. 生成步骤清晰、预期结果可观察的测试用例。
3. 如果 PRD 定义了输入限制，请覆盖正常值、最小值、最小值-1、最大值、最大值+1，以及适用时的空值。
4. 最终导出为 xlsx。
```

## 最终列结构

默认列：

- `用例编号`
- `模块`
- `用例标题`
- `前置条件`
- `测试步骤`
- `预期结果`
- `优先级`
- `类型`
- `备注`

追加的执行列：

- `实际结果`
- `执行人`
- `执行日期`
- `是否通过`
- `需求编号`
- `是否自动化`

这样既能保持基础 schema 稳定，也能适配希望直接在 Excel 里执行测试的团队。
